     1→# TA Workbench — Forex & Binary Options Technical Analysis Platform
     2→
     3→A user-defined technical-analysis platform: **you** create, organize, version and
     4→evaluate your own trading strategies. The platform is *not* a signal generator,
     5→has no built-in mandatory indicators or trading rules, executes **no orders**,
     6→and **never fabricates market data**.
     7→
     8→**Phase 2 (this repository)** delivers the MetaTrader 5 market-data
     9→integration on top of the Phase 1 foundation (FastAPI + PostgreSQL, versioned
    10→whitelisted rule format, explainable evaluator, Next.js/TypeScript frontend,
    11→Docker Compose, full test suites): a real MT5 adapter with bounded reconnects,
    12→validated candle data with explicit quality warnings, a PostgreSQL historical
    13→cache, market-data endpoints and a live market preview in the UI. Strategy
    14→analysis on LIVE candles and backtesting remain future phases.

    18→## Product principles
    19→
    20→| Principle | Implementation |
    21→|---|---|
    22→| User-defined strategies | Users build their own categories, strategies, conditions, AND/OR groups, confirmation & invalidation rules. Nothing is imposed. |
    23→| Explainable analysis | Every evaluation returns a per-condition tree: met / missing, numeric evidence, criteria and data-quality warnings. |
    24→| Explicit whitelist | Condition types, operators, fields, group logic, modes and timeframes are enumerated server-side (`/api/v1/meta`); anything else is rejected with precise error paths. |
    25→| Versioned rule sets | Saving a rule set creates a NEW immutable version (`strategy_versions` table). History is never rewritten — ready for later backtesting. |
    26→| No arbitrary code execution | Rule sets are pure data interpreted by a deterministic evaluator. No `eval`, no user expressions. |
    27→| Forex / Binary Options separation | Separate modes everywhere: API filtering, rule validation (Binary Options = M1 only by product rule), and default timeframe profiles (Forex: D1, H4, H1, M15, M5, M1). |
    28→| Honest market data | If MetaTrader 5 is not connected the API and UI say so plainly and serve NOTHING. Every candle payload carries `data_provenance` (`mt5_live` / `postgres_cache`), `data_status` and data-quality warnings (gaps, duplicates, invalid OHLC, staleness). Forming candles are flagged and can be excluded with `closed_only=true`. |
    29→| No fabricated prices | The MT5 adapter is the only data source; missing history is reported, never back-filled, interpolated or synthesized. |

    59→### MT5 integration topology (important)
    60→
    61→The `MetaTrader5` Python package only runs where the terminal runs.
    62→
    63→- **Recommended**: run the backend **natively on the Windows host** with the
    64→  MT5 terminal installed, running and logged in. `pip install -r
    65→  requirements-mt5.txt`, set `DATABASE_URL` (plus optional `MT5_*` settings),
    66→  start uvicorn. The backend attaches to the terminal via its IPC bridge.
    67→- **Wine**: possible with Windows Python under Wine, unsupported here — test
    68→  carefully before relying on it.
    69→- **Docker Compose (Linux containers)**: MT5 **cannot** run inside the
    70→  container. Compose therefore starts the backend with `MT5_ENABLED=false`
    71→  (safe disabled mode — API and UI report it honestly). PostgreSQL and the
    72→  rest of the platform keep working; alternatively point the frontend at a
    73→  backend running on a Windows machine via `NEXT_PUBLIC_BACKEND_ORIGIN`.
    74→- **Security model**: credentials (if any) exist ONLY in environment
    75→  variables; no endpoint accepts credentials, terminal paths or anything
    76→  executable; the terminal is never exposed to the public internet; if the
    77→  API is reachable remotely, put it behind your own auth proxy / VPN
    78→  (built-in authentication is a later phase) and restrict the network.
    79→- **Timestamps**: candle times are preserved exactly as MT5 reports them —
    80→  epoch seconds whose wall-clock value is the BROKER SERVER time (the MT5
    81→  convention). Every response also renders the same epoch as ISO-8601 UTC
    82→  (`time_utc`) and carries `timezone: "MT5_SERVER"` with a human-readable
    83→  `timezone_note`. Nothing is ever re-based silently.

   143→## API conventions
   144→
   145→Every response uses the same envelope (`app/core/responses.py`):
   146→
   147→```json
   148→// success
   149→{ "success": true,  "data": { ... }, "error": null,
   150→  "meta": { "request_id": "…", "timestamp": "…", "api_version": "v1" } }
   151→
   152→// error
   153→{ "success": false, "data": null,
   154→  "error": { "code": "RULE_VALIDATION_FAILED", "message": "…", "details": [ { "path": ".conditions[0].operator", "message": "…", "code": "unsupported_operator" } ] },
   155→  "meta": { "request_id": "…" } }
   156→```
   157→
   158→The `request_id` is also returned in the `X-Request-ID` header and appears in
   159→the server's structured logs — quote it when reporting issues.
   160→
   161→### Endpoints
   162→
   163→| Method & path | Purpose |
   164→|---|---|
   165→| `GET /health/live` | Liveness (no dependencies). |
   166→| `GET /health/ready` | Readiness: PostgreSQL probe + market-data status (503 when DB down). |
   167→| `GET /api/v1/meta` | Modes, default timeframes, rule-format whitelists, market-data info. |
   168→| `GET /api/v1/market-data/status` | Honest MT5 availability report (live check). |
   169→| `GET /api/v1/mt5/status` | MT5 terminal/account connection report + safe config summary. **No credentials ever.** |
   170→| `GET /api/v1/market/symbols` | Symbols known to the terminal (`?search=EUR*&limit=100`). |
   171→| `GET /api/v1/market/candles` | Validated OHLCV series (`?symbol=&timeframe=&limit=&closed_only=&refresh=`). |
   172→| `GET /api/v1/market/tick` | Latest tick / bid-ask / spread for one symbol. |
   173→| `GET /api/v1/market/diagnostics` | End-to-end diagnostics: connection + live candle probe + capabilities. |
   174→| `GET/POST /api/v1/strategy-categories` | List/create categories (+`?mode=` filter). |
   175→| `GET/PATCH/DELETE /api/v1/strategy-categories/{id}` | Manage a category. |
   176→| `GET/POST /api/v1/strategies` | List/create strategies (+`mode`, `category_id`, `status`). |
   177→| `GET/PATCH/DELETE /api/v1/strategies/{id}` | Detail (incl. current rule set) / update / delete. |
   178→| `POST /api/v1/strategies/{id}/versions` | Validate + save a NEW immutable version. |
   179→| `GET /api/v1/strategies/{id}/versions[/{n}]` | Version history / specific version. |
   180→| `POST /api/v1/rule-sets/validate` | Validate a rule set without saving (editor support). |
   181→| `POST /api/v1/analysis/evaluate` | Explainable evaluation on user-supplied candles. |
   182→
   183→Structured errors from the market endpoints:
   184→
   185→| HTTP | Code | When |
   186→|---|---|---|
   187→| 422 | `VALIDATION_ERROR` | Bad symbol/timeframe/limit (precise `details[].path`). |
   188→| 404 | `SYMBOL_NOT_FOUND` | Symbol unknown to the terminal. |
   189→| 502 | `MARKET_DATA_ERROR` | Terminal returned an unusable/empty response. |
   190→| 503 | `MARKET_DATA_UNAVAILABLE` | MT5 disabled, package missing or terminal unreachable. |

   193→
   194→```jsonc
   195→{
   196→  "success": true,
   197→  "data": {
   198→    "symbol": "EURUSD", "timeframe": "M1",
   199→    "timezone": "MT5_SERVER",
   200→    "timezone_note": "Candle timestamps are preserved exactly as reported by MetaTrader 5 …",
   201→    "candles": [
   202→      { "time": 1731608940, "time_utc": "2024-11-14T17:09:00+00:00",
   203→        "open": 1.05651, "high": 1.05662, "low": 1.0564, "close": 1.05655,
   204→        "volume": 812, "forming": false }
   205→      // … newest last; forming candles flagged with "forming": true
   206→    ],
   207→    "count": 3, "requested_count": 3, "closed_only": true, "includes_forming": false,
   208→    "first_time": 1731608940, "last_time": 1731609120,
   209→    "newest_closed_time": 1731609120, "newest_closed_age_seconds": 42.1,
   210→    "data_status": "ok",              // ok | partial | stale | insufficient | empty
   211→    "data_provenance": "mt5_live",    // mt5_live | postgres_cache
   212→    "retrieved_at": "2024-11-14T17:09:37.123+00:00",
   213→    "warnings": [                     // e.g. GAPS_DETECTED, STALE_DATA, INVALID_OHLC…
   214→      { "code": "GAPS_DETECTED", "severity": "warning", "message": "1 gap(s) … NOT back-filled" }
   215→    ]
   216→  },
   217→  "error": null,
   218→  "meta": { "request_id": "…", "timestamp": "…", "api_version": "v1" }
   219→}
   220→```
   221→
   222→**Caching & data distinction.** Raw MT5 responses are validated in-process
   223→(`validation.py`) and — when fresh enough per timeframe — served from the
   224→PostgreSQL `candles` cache (`data_provenance: "postgres_cache"`); otherwise
   225→they are fetched live (`mt5_live`) and persisted. Duplicate inserts are
   226→impossible (composite PK + upsert); the full history is never loaded per
   227→request; a dedicated `refresh=true` request bypasses the cache. No Redis.
   228→
   229→Interactive docs: `http://localhost:8000/docs` (disabled when `APP_ENV=production`).

   231→### The versioned rule format (schema `1.0`)
   232→
   233→```jsonc
   234→{
   235→  "schema_version": "1.0",
   236→  "mode": "forex",                          // forex | binary_options
   237→  "timeframes": ["H1", "M15"],              // must be declared here first
   238→  "direction": "bullish",                   // bullish | bearish
   239→  "conditions": {                           // root group (required)
   240→    "logic": "AND",                          // AND | OR
   241→    "conditions": [
   242→      { "id": "trend_hold", "type": "price_level", "field": "close",
   243→        "operator": "above", "value": 1.0850,
   244→        "timeframe": "H1", "lookback": 20 }
   245→    ],
   246→    "groups": [ /* nested AND/OR groups (max depth 4) */ ]
   247→  },
   248→  "confirmation": { "logic": "AND", "conditions": [ /* … */ ] },  // optional
   249→  "invalidation": { "logic": "AND", "conditions": [ /* … */ ] },  // optional
   250→  "notes": "free-form user documentation (optional)"
   251→}
   252→```
   253→
   254→**Phase 1 whitelist** (extended in Phase 2 by registry entries, not format
   255→changes): condition type `price_level`; price fields `open, high, low, close`;
   256→operators `above, below, crosses_above, crosses_below`; timeframes
   257→`M1, M5, M15, H1, H4, D1`; lookback 1–500; ≤ 100 conditions; ≤ 25 per group.
   258→
   259→**Evaluation semantics** (deterministic, documented, tested):
   260→
   261→- `above`/`below` — satisfied when the **latest candle** in the lookback window
   262→  satisfies the comparison; evidence reports matched count and timestamps.
   263→- `crosses_above`/`crosses_below` — satisfied when the **latest candle**
   264→  completes the cross; evidence lists every cross in the window.
   265→- Group `AND` = all children satisfied; `OR` = at least one.
   266→- Result status: `conditions_met`, `conditions_missing`, `invalidated`
   267→  (invalidation group satisfied), or `insufficient_data` (referenced timeframe
   268→  has no usable candles — the platform never invents data).

   322→The frontend calls the backend through one of two modes
   323→(`src/lib/api/client.ts`):
   324→

   326→  the same origin with `?XTransformPort=8000` — used by the sandbox preview and
   327→  single-domain deployments.
   328→- **Direct mode**: set `NEXT_PUBLIC_BACKEND_ORIGIN=http://localhost:8000`
   329→  (already the default in `.env.example` for Compose) and add the frontend
   330→  origin to backend `CORS_ORIGINS`.

   332→### Option C — Windows host with a live MT5 terminal (live market data)
   333→
   334→1. Install & start the MetaTrader 5 terminal; log in to your broker.
   335→2. `pip install -r backend/requirements-mt5.txt` in the backend venv.
   336→3. Configure `backend/.env`: `DATABASE_URL` (a reachable PostgreSQL),
   337→   `MT5_ENABLED=true`. Prefer leaving `MT5_LOGIN/PASSWORD/SERVER` empty so the
   338→   backend attaches to the terminal's own login — no credentials stored.
   339→4. `cd backend && alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port 8000`
   340→5. Verify: `curl http://localhost:8000/api/v1/mt5/status` →
   341→   `"connected": true`, then open the frontend's **Market** tab.

   442→## Troubleshooting
   443→
   444→| Symptom | Cause & fix |
   445→|---|---|
   446→| Backend exits: `DATABASE_URL …` | Config invalid/missing. Copy `backend/.env.example` → `backend/.env` and set a real PostgreSQL URL. |
   447→| Backend exits: `MT5_LOGIN … MT5_PASSWORD/MT5_SERVER` | Partial MT5 credentials. Provide all three or none (recommended: none — attach to the logged-in terminal). |
   448→| `/health/ready` returns 503, database `down` | PostgreSQL unreachable. `docker compose up -d db`, or let `make backend` provision a local pgserver cluster. The app keeps running and reports honestly. |
   449→| Frontend shows “backend unreachable” | Backend not started. Run `make backend` (or `docker compose up -d backend`). |
   450→| `/api/v1/mt5/status`: package “not installed” | The `MetaTrader5` package is missing or you are on Linux/macOS. Install `backend/requirements-mt5.txt` on the Windows host with the terminal. The API stays honest — no data is faked. |
   451→| `/api/v1/mt5/status`: “Could not connect … after N attempt(s)” | Terminal not running/not logged in. Start & log into MT5, wait ~30s (reconnect cooldown), then press “Check now”. |
   452→| `MARKET_DATA_UNAVAILABLE` (503) with `MT5_ENABLED=false` | Disabled mode (e.g. Docker Compose default). Enable MT5 on a Windows host or run analysis on user-supplied candles. |
   453→| `SYMBOL_NOT_FOUND` | The symbol is unknown to this terminal. Check `GET /api/v1/market/symbols`; some brokers suffix symbols (`EURUSD.i`). |
   454→| `MARKET_DATA_ERROR` “no rate history” | The symbol exists but has no data for that timeframe/history depth. Try another timeframe or a smaller `limit`. |
   455→| Candle response says `STALE_DATA` / `GAPS_DETECTED` | The terminal is serving old or gapped history (market closed, low liquidity, or symbol recently selected). Warnings are informational; nothing is back-filled. |
   456→| Port 8000 already in use | Another backend instance is running — `make backend` detects and skips. Change `API_PORT` if needed. |
   457→| `rule-sets/validate` returns `RULE_VALIDATION_FAILED` | Read `error.details[].path` — each entry pinpoints the exact violation against the whitelist. |

   459→## Known limitations (Phase 2)
   460→
   461→1. **No authentication / multi-tenancy yet** — all data belongs to the single
   462→   local user. If the API is reachable beyond localhost, front it with your
   463→   own auth proxy; built-in auth arrives in a later phase.
   464→2. **Real-terminal behaviour is implemented but was NOT exercised** — the
   465→   sandbox cannot run MetaTrader 5. All automated tests use a faithful fake;
   466→   use the documented live procedure above to validate a specific broker
   467→   terminal. Until then, treat live behaviour as unverified.
   468→3. **WebSockets/streaming** are not implemented — the frontend polls every
   469→   15–30 s. Planned next.
   470→4. **Analysis does not consume MT5 candles yet** — `POST
   471→   /api/v1/analysis/evaluate` still evaluates user-supplied candles; wiring
   472→   the evaluator to live `mt5_live` series (explicit provenance label) is the
   473→   next phase.
   474→5. **Condition types are limited to `price_level`** by design; the registry is
   475→   built so indicator conditions slot in without format changes.
   476→6. **No automatic trading or order execution** — permanently out of scope;
   477→   nothing here sends orders anywhere.
   478→7. The cache serves at most the configured `limit` of latest candles per
   479→   series; deep historical backfill (beyond the terminal's own depth) is not
   480→   attempted.
   481→8. `docker compose` builds the frontend in dev mode; the production build
   482→   path (`Dockerfile.frontend`) was not exercised inside the sandbox.
   483→
   484→## Recommended next step: Phase 3 — live evaluation & backtesting
   485→
   486→1. Wire the evaluator to MT5 candles: `POST /api/v1/analysis/evaluate-live`
   487→   (explicit `data_provenance: "mt5_live"`), reusing the validated
   488→   `CandleSeries` pipeline.
   489→2. WebSocket streaming of candle updates + status changes; the frontend
   490→   client already isolates all backend I/O in one module.
   491→3. Historical analysis & backtesting over stored immutable strategy versions;
   492→   the `candles` cache is the natural replay source.
   493→4. Optional: indicator condition types registered against the same whitelist
   494→   mechanism (no format change required).
